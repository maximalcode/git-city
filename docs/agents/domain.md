# Domain docs

This is a single-context repository. Its glossary belongs in the root
`CONTEXT.md`; architecture decisions belong in `docs/adr/`.

Before exploring code, read `CONTEXT.md` and the ADRs relevant to the area.
If either is absent, proceed silently. The `domain-modeling` skill creates
these documents when terminology or decisions are resolved.

Use glossary terms consistently in issue titles, proposals, hypotheses, and
tests. If a concept is missing, reconsider whether it belongs to the domain;
record real vocabulary gaps through the repository's issue workflow for
`domain-modeling`.

If a proposal contradicts an existing ADR, cite that ADR and explain why its
decision should be reopened.
